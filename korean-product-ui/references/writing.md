# 화면 문구

디자인이 깔끔해도 문구가 번역투거나 과장돼 있으면 AI가 만든 화면처럼 읽힌다.
기준은 토스가 공개한 라이팅 원칙과 앱인토스 UX 라이팅 가이드를 바탕으로, 일반 서비스에 맞게 줄였다.

## 말투

- **해요체 하나로 통일한다.** "저장했어요", "다시 시도해 주세요". 한 화면에 "~합니다"와 "~해요"가 섞이면 바로 티가 난다(`copy-tone-mix`).
  약관 본문·법적 고지처럼 원래 합쇼체인 글은 `<footer>`나 `data-kpui-ignore` 안에 두면 검사에서 빠진다.
- 과한 높임말을 뺀다: "확인하시겠어요?" → "확인할까요?", "고객님께" → "회원님에게"는 상황에 따라.
- 능동형으로: "저장되었습니다" → "저장했어요". "되어지다"는 틀린 이중 피동이다(`copy-double-passive`).
- 소리 내어 읽었을 때 자연스러운지 본다. 한자어 명사를 잇대지 말고 풀어 쓴다: "본인인증 진행" → "본인 확인하기".

## 줄이기

토스는 이걸 세 층으로 나눈다. 문장 안의 군더더기, 화면 안에서 반복되는 문장, 화면과 화면 사이의 중복.

- 빼도 뜻이 같은 말을 지운다: "혹시", "지금 바로", "다양한", "쉽고 빠르게", "~할 수 있습니다"(`copy-weed`).
- 제목에서 한 말을 설명에서 또 하지 않는다. 설명이 제목을 반복하면 설명을 지운다.
- 한 화면에는 핵심 메시지 하나. 부가 정보는 접거나 다음 화면으로.

## 버튼(CTA)

- 버튼만 읽어도 **누르면 무슨 일이 일어나는지** 알 수 있어야 한다: "확인" 대신 "예약하기", "다음" 대신 "결제 수단 고르기".
- "클릭하세요", "여기를 누르세요"는 쓰지 않는다. 행동 자체를 버튼 이름으로 쓴다(`copy-click`).
- 다이얼로그의 닫는 버튼은 "닫기". "취소"는 하던 작업이 취소된다고 읽힐 수 있다.
- 강요 대신 제안: "지금 가입하세요!" → "가입하고 쿠폰 받기".

## 오류·빈 화면

- 무엇이 안 됐는지보다 **어떻게 하면 되는지**를 먼저: "비밀번호가 틀렸어요" + "비밀번호 찾기".
- 사용자 탓으로 읽히지 않게: "잘못 입력하셨습니다" → "숫자 6자리를 입력해 주세요".
- 빈 화면에는 그 자리에 무엇이 쌓이는지와 첫 행동 하나: "아직 예약이 없어요" + "공간 둘러보기".

## 쓰지 않는 것

- 문구 속 이모지(🚀✨🔥). 아이콘이 필요하면 SVG로 따로 둔다(`emoji-icon`).
- 느낌표 남발. 강조는 크기·굵기·위치로 한다(`copy-exclaim`).
- "혁신적인", "새로운 경험", "당신의 일상을 특별하게" 같은 내용 없는 헤드라인. 무엇을 하는 서비스인지 구체적으로 쓴다.
- 거절을 부끄럽게 만드는 문구("혜택 포기하기", "손해 볼게요"). 그냥 "괜찮아요", "다음에 할게요"(`dark-confirmshaming`).
- lorem ipsum, "텍스트를 입력하세요" 같은 자리표시 문구(`placeholder-text`). 예시 화면에도 실제 같은 데이터를 넣는다.
