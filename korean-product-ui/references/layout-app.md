# 앱 화면

국내 소비자 앱(금융, 커머스, 예약, 커뮤니티)이 공통으로 쓰는 뼈대다. 특정 서비스를 베끼는 게 아니라
사용자가 이미 익숙한 위치에 익숙한 것을 두는 것이 목적이다.

## 기준 폭과 여백

- 기준 화면 390×844(아이폰 14·15 계열). 360 폭 안드로이드에서도 깨지지 않는지 본다.
- 좌우 여백 20px. 카드 안쪽 16–20px. 섹션 사이 32–40px, 섹션 안 요소 사이 12–16px.
- 간격은 4의 배수로만 쓴다(4, 8, 12, 16, 20, 24, 32, 40).

## 화면 구조

```
┌ 상단 바(48–56px): 뒤로 가기 · 화면 제목(가운데 또는 왼쪽) · 보조 액션 1–2개
│
│  큰 제목(선택): 22–26px, 화면의 목적을 한 문장으로
│  본문: 목록·카드·폼
│
├ 하단 고정 CTA(선택): 화면당 1개, 좌우 20px 여백, 높이 52–56px, 위로 흰 그라데이션 페이드
└ 하단 탭(최상위 화면에만): 4–5개, 아이콘+라벨, 높이 56px + safe area
```

- 최상위 화면(홈·검색·내역·마이)에만 하단 탭. 상세·결제 같은 하위 화면에서는 숨기고 하단 CTA를 둔다.
- 하단 CTA는 화면의 **유일한** 주 행동이다. 보조 행동은 텍스트 버튼이나 상단 바로 보낸다.
- 하단 고정 요소가 있으면 본문 맨 아래에 그만큼 여백을 줘서 마지막 항목이 가려지지 않게 한다.

## 목록이 기본이다

국내 앱은 카드 그리드보다 **목록(row)** 을 많이 쓴다. 한 화면에 더 많은 정보를 보여 주고, 훑어보기 쉽다.

- 목록 한 줄: 왼쪽 썸네일/아이콘(40–72px) · 가운데 제목+보조 정보 2줄 · 오른쪽 값(금액, 상태)이나 화살표.
- 줄 사이는 1px 구분선(#F2F4F6 정도) 또는 여백만. 줄마다 그림자 카드로 만들지 않는다.
- 섹션은 굵은 제목 + 오른쪽 "전체보기" 텍스트 버튼. 섹션 사이를 8px 회색 띠(#F2F4F6)로 나누는 방식도 흔하다.
- 정보 밀도를 겁내지 않는다. 가격·평점·거리·남은 시간처럼 결정에 필요한 숫자는 목록에서 바로 보이게.

## 컴포넌트 기본값

- **터치 영역** 44×44px 이상. 아이콘이 24px여도 버튼 영역은 44px(`touch-target`).
- **버튼**: 주 버튼은 채운 강조색, 보조는 연한 회색 바탕(#F2F4F6)에 진한 글자. 테두리만 있는 버튼은 드물게.
  모서리 12–16px. 높이 큰 버튼 52–56, 중간 40–44, 작은 32(작은 버튼은 터치 영역을 따로 확보).
- **입력창**: 라벨은 위에, 플레이스홀더는 예시로만. 오류는 아래 빨간 글자 한 줄. 높이 52px 안팎.
- **바텀시트**: 선택지 고르기, 확인 받기에 쓴다. 손잡이 바, 제목, 내용, 하단 버튼. 진입하자마자 띄우지 않는다.
- **토스트/스낵바**: 하단 CTA 위에 잠깐. 되돌리기가 있으면 "실행 취소" 텍스트 버튼.
- **칩/세그먼트**: 필터에 가로 스크롤 칩. 선택된 칩은 진한 배경+흰 글자.
- **배지**: 숫자나 짧은 상태("오늘 마감", "N")만. 남발하면 다 같이 안 보인다.

## 상태

모든 화면에 이 네 가지가 있는지 확인한다.

- 로딩: 레이아웃 모양 그대로의 스켈레톤. 화면 가운데 스피너 하나만 두지 않는다.
- 빈 화면: 무엇이 여기 쌓이는지 + 첫 행동 버튼 하나.
- 오류: 무엇을 하면 되는지 + 다시 시도.
- 긴 텍스트·큰 숫자: 상호명이 길 때, 금액이 1,000,000원을 넘을 때 줄이 넘치지 않는지.
