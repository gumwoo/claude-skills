검사기는 `${CLAUDE_SKILL_DIR}/scripts/check-ui.mjs`다. Node.js 22 이상과 설치된 Chrome·Edge·Chromium이 필요하고, 외부 패키지는 쓰지 않는다.
브라우저를 못 찾으면 `CHROME_PATH` 환경변수로 실행 파일을 지정하라고 안내한다.

## 원칙

- 특정 브랜드를 복제하지 않는다. 로고·고유 일러스트·브랜드 색을 가져오지 않고, 여러 서비스가 공유하는 관습(목록 구조, 하단 CTA, 해요체)을 따른다.
- 강조색은 하나. 프로젝트에 정해진 색이 있으면 그것을, 없으면 사용자에게 묻거나 업종에 맞는 색 하나를 골라 이유를 한 줄로 쓴다. 보라·남색 그라데이션은 쓰지 않는다.
- 프로젝트에 디자인 시스템(당근 SEED, 토스 TDS, 원티드 Montage, 자체 시스템)이 있으면 그 토큰과 컴포넌트를 우선한다. 이 스킬의 값은 그게 없을 때의 기본값이다.
- 예시·목업에도 실제 같은 데이터를 쓴다. 이름·가격·평점·후기 수가 제각각이어야 한다.
- "깔끔하다", "AI 티가 안 난다"는 검사 결과와 스크린샷을 보고 나서만 말한다.

## 1. 맥락 파악

먼저 확인한다(코드에서 알 수 있으면 묻지 않는다).

- 플랫폼: 앱(네이티브 감성의 모바일 화면) / 모바일 웹 / 데스크톱 웹 / 반응형
- 업종과 화면의 목적: 무엇을 고르고, 무엇을 결정하고, 무엇을 누르게 하는 화면인가
- 기존 스택: 프레임워크, CSS 방식(Tailwind·CSS Modules·styled 등), 기존 토큰·컴포넌트
- 강조색과 글꼴이 이미 정해져 있는지

## 2. 토큰 정하기

디자인 시스템이 없으면 `${CLAUDE_SKILL_DIR}/templates/tokens.css`를 프로젝트 방식에 맞게 옮긴다.
Tailwind면 theme 확장으로, CSS-in-JS면 테마 객체로 바꾼다. 최소한 이것은 지킨다.

- 글꼴: Pretendard(또는 SUIT·Wanted Sans 중 하나) + 시스템 한글 글꼴 대체 스택
- `word-break: keep-all; overflow-wrap: break-word;` 를 body에
- 본문 16px·줄 간격 1.5 안팎, 큰 제목 자간 -0.02em
- 회색 글자 단계, 1px 구분선 색, 강조색 하나

## 3. 만들기

화면 종류에 맞는 문서를 읽고 만든다. 필요한 것만 읽는다.

| 무엇을 | 읽을 문서 |
|---|---|
| 앱·모바일 화면 구조, 목록, 하단 CTA, 컴포넌트 기본값 | `references/layout-app.md` |
| 웹 폭·그리드·헤더·첫 화면·상세·푸터 | `references/layout-web.md` |
| 글꼴·줄바꿈·크기·숫자 표기 | `references/typography.md` |
| 버튼 이름, 해요체, 오류·빈 화면 문구 | `references/writing.md` |
| 동의·팝업·결제 흐름 | `references/dark-patterns.md` |
| 다 만든 뒤 자기 검토 | `references/ai-tells.md` |

만들 때 놓치기 쉬운 것:

- 로딩·빈 화면·오류 상태와 긴 텍스트·큰 금액을 같이 만든다.
- 금액은 `toLocaleString('ko-KR')`로 쉼표를 넣고 단위를 붙인다.
- 버튼 이름은 누르면 일어나는 일로("예약하기", "결제 수단 고르기"). "확인", "클릭하세요"는 피한다.
- 선택 동의는 기본 해제. 진입 팝업, 뒤로 가기 가로채기는 만들지 않는다. 요청받았으면 만들되 문제를 한 줄로 알린다.

## 4. 그려서 검사

만든 화면을 실제로 그려서 검사한다. 개발 서버가 있으면 URL로, 정적 파일이면 파일 경로로.

```bash
node "${CLAUDE_SKILL_DIR}/scripts/check-ui.mjs" <파일|URL> --viewport both --shot <저장경로>/screen.png --full
```

- 모바일(390×844)과 데스크톱(1440×900)에서 각각 검사하고, `screen-mobile.png`·`screen-desktop.png`를 남긴다.
- 종료 코드: 0 = ERROR 없음, 2 = ERROR 있음, 1 = 실행 실패.
- 결과는 세 단계다.
  - **ERROR**: 고친다. 어절 중간 줄바꿈, 쉼표 없는 금액, 가로 넘침, 읽기 어려운 대비, 미리 체크된 선택 동의.
  - **WARN**: 대부분 고친다. 고치지 않는다면 이유를 보고에 쓴다(예: 의도적으로 작은 법적 고지).
  - **INFO**: 판단해서 고친다.
- 규칙이 틀렸다고 판단되면(오탐) 고치지 말고 보고에 그대로 적는다. 검사를 통과시키려고 문구를 어색하게 바꾸지 않는다.

그다음 **스크린샷을 직접 열어 보고** `references/ai-tells.md` 목록과 대조한다. 검사기가 못 잡는 것(카드 남발, 가운데 정렬, 빈 헤드라인, 가짜 데이터, 위계 없는 화면)은 눈으로만 잡힌다.

고치고 다시 검사하기를 최대 3번 반복한다. 3번 안에 ERROR가 남으면 멈추고 남은 것을 보고한다.
