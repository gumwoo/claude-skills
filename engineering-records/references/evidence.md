# 숫자에 원자료 달기

문서에 쓴 측정 숫자 바로 뒤에 HTML 주석으로 출처를 단다. 렌더링된 문서에는 보이지 않고,
`verify-numbers.mjs`가 그 파일에서 값을 꺼내 문서 숫자와 대조한다.

```
850ms <!-- src: <파일> :: <선택자> [*배율 | /배율] [~허용%] -->
```

- **파일**: 문서 위치 기준 상대 경로, 없으면 저장소 루트 기준.
- **선택자**
  - JSON: 점과 대괄호 경로. 키에 괄호·점이 있으면 `["..."]`로 쓴다.
    - `result.overSold`
    - `metrics.http_req_duration.values["p(95)"]` (k6 `--summary-export` 결과)
    - `runs[2].ms`
  - 텍스트: `/정규식/` — 첫 번째 괄호 그룹(없으면 맞은 전체)을 숫자로 읽는다.
    - `/http_req_failed[^\n]*?(\d+\.\d+)%/`
    - `/Tests run: (\d+)/`
- **배율**: 단위가 다를 때. 원자료가 초이고 문서가 ms면 `*1000`, 원자료가 바이트이고 문서가 MB면 `/1048576`.
- **허용 범위**: 기본은 "문서에 쓴 자릿수로 반올림해서 같으면 일치"다(문서 850, 원자료 849.6 → 일치). 근사값을 일부러 쓸 때만 `~2%`처럼 붙인다.

## 예

```markdown
| 지표 | before | after | 변화 |
|------|--------|-------|------|
| 초과 판매 | 19건 <!-- src: ../../benchmarks/oversell-before.json :: result.overSold --> | 0건 <!-- src: ../../benchmarks/oversell-after.json :: result.overSold --> | -100% |
| p95 | 1,180ms <!-- src: ../../benchmarks/search-before.json :: metrics.http_req_duration.values["p(95)"] --> | 310ms <!-- src: ../../benchmarks/search-after.json :: metrics.http_req_duration.values["p(95)"] --> | -74% |
| 처리 시간 | 2,400ms <!-- src: ../../benchmarks/batch-before.txt :: /elapsed: (\d+\.\d+)s/ *1000 --> | 620ms <!-- src: ../../benchmarks/batch-after.txt :: /elapsed: (\d+\.\d+)s/ *1000 --> | 3.9배 |
```

변화 열(`변화`, `change`, `diff`, `증감`)은 출처를 달지 않는다. 검사기가 같은 행의 before·after로 다시 계산해서
`-74%`, `+11.6x`, `3.9배` 같은 값이 맞는지 본다. 숫자만 보고 계산하므로 한 행의 before·after는 단위를 맞춰 쓴다
(1.2s와 310ms를 섞지 말고 1,200ms와 310ms로). 원자료 단위가 다르면 배율(`*1000`)로 맞춘다.

## 출처를 달 수 없는 숫자

- **예측·목표·가정**: 같은 줄에 "예측", "추정", "예상", "목표", "가정"을 쓴다. 검사기는 그 줄을 출처 요구에서 뺀다.
- **측정 안 함**: 숫자 대신 "측정 안 함"이라고 쓴다.
- **시험 조건**: 스레드 수 20, 50 VU, 5분 같은 조건은 `- 조건: 50 VU, 5분, 워밍업 1분`처럼 "조건:"(또는 "측정 조건:", "환경:")으로 시작하는 줄에 모아 쓴다. 검사기는 그 줄을 출처 요구에서 뺀다. 표 안에 조건을 넣었다면 원자료의 `config` 같은 필드에 출처를 단다.

## 검사기가 측정 숫자를 찾는 곳

- before·after 열이 있는 표(GFM: 머리 행 바로 다음 줄이 `---` 구분선. 앞뒤 `|`가 없거나 인용 `>` 안에 있어도 된다). 열 이름 안에 `before`, `baseline`, `전`, `이전`, `기존`, `수정 전`·`변경 전` / `after`, `optimized`, `후`, `이후`, `수정 후`·`변경 후` / `변화`, `변화율`, `증감`, `개선율`, `향상`, `change`, `diff`, `delta`, `Δ`, `speedup`이 독립된 낱말로 있으면 알아본다. `Before p95`, `전(ms)`, `before<br>(ms)`는 잡고, `전체 요청`, `전송량`처럼 단어 일부로는 잡지 않는다. `기존 | 개선 | 개선율`처럼 쓰면 `개선`을 after로 본다.
- 제목에 증상·결과·측정·재측정·성능·before·after·result·metric이 들어간 절. 단, 제목에 "조건"·"방법"이 있거나 결정 기록(ADR 폴더) 안의 절은 뺀다.

식별자(`IMP-003`), 날짜, 시간, 버전, `p95`의 95, 커밋 해시(글자가 섞인 7자 이상), 링크, 인라인 코드, 코드 블록 안의 숫자는 측정값으로 보지 않는다.

변화 열의 방향: 부호(`-75%`, `–75%`), 화살표·삼각형(`75%↓`, `▼75%`, `▲75%`, 회계식 음수 `△75%`), 말(`75% 감소`) 중 하나라도 있으면 실제 방향과 맞아야 한다.

출처 표시는 한 줄 안에 써야 한다. 대소문자(`SRC`)와 콜론 앞 공백(`src :`)은 상관없다. 여러 줄에 걸친 표시는 검사할 수 없어 오류로 알린다.

문서 숫자 뒤에 `%`가 붙어 있는데 원자료 값이 0~1 사이(k6의 `rate` 같은 비율)이면, 반올림으로 우연히 맞은 것일 수 있어 오류로 알린다. 비율이면 `*100`, 이미 %면 `*1`을 출처 표시에 붙인다. 방향 표시가 없으면 크기만 본다. 배수는 1 이상이면 큰 쪽÷작은 쪽(`3배 빨라짐`), 1 미만이면 after÷before(`0.25x`)로 계산한다.
