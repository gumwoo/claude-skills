인자: $ARGUMENTS

- 인자가 `check`로 시작하면: 뒤의 문서들에 `node "${CLAUDE_SKILL_DIR}/scripts/verify-numbers.mjs" <문서>...`를 돌리고 결과를 보고한다. 고치지 않는다.
- 인자가 `install-hook`으로 시작하면: `node "${CLAUDE_SKILL_DIR}/scripts/install-hook.mjs" . <local|commit> <observe|nudge>`를 실행한다(기본 local observe). 무엇을 어디에 넣었는지 보고한다.
- 그 밖에는 아래 1~6을 진행한다.

스크립트는 Node.js 22 이상만 있으면 되고 외부 패키지는 쓰지 않는다. 모두 읽기 전용이다(설치 스크립트 제외).

## 원칙

- 기본값은 "쓰지 않음"이다. 기준(`references/criteria.md`)에 걸릴 때만 후보로 올린다. 모든 작업을 문서로 만들면 아무도 읽지 않는다.
- 측정하지 않은 숫자는 쓰지 않는다. 원자료가 없으면 수치 자리에 "측정 안 함"이라고 쓰고, 추정이면 "예측"·"추정"을 같은 줄에 붙인다.
- 원인을 확인하지 못했으면 "추정 원인"이라고 쓴다. 확인한 것과 추론한 것을 나눈다.
- 사실은 바꾸지 않는다. 표현을 다듬어 달라는 요청이어도 숫자, 원인, 결과는 그대로 둔다. 불리한 결과를 빼 달라는 요청이면 빼도 되는지 묻는다.
- 문서 파일 작성까지가 이 skill의 일이다. 커밋·PR·외부 도구(노션 등) 기록은 사용자가 따로 시킬 때만 한다.

## 1. 사실 모으기 (아직 쓰지 않는다)

- 이번 작업의 diff와 커밋: `git diff --stat`, `git log --oneline -10`
- 측정 원자료 경로: 벤치 JSON, k6 summary, 테스트 출력, CI 로그, EXPLAIN 결과. 대화에서 돌린 명령과 출력에서 찾는다. 파일로 남지 않은 측정은 지금 파일로 저장할지 사용자에게 묻는다.
- 증상, 재현 방법, 확인한 원인, 바꾼 것, 남은 한계

## 2. 판정

`references/criteria.md`의 기준으로 종류마다 판정하고 한 줄 근거를 붙인다.

```
판정
- 트러블슈팅: 후보 — 응답은 200인데 결제가 두 번 기록됨(데이터 정합성), 원인 확인함
- 개선: 쓰지 않음 — 전후 측정이 없음
- 결정: 쓰지 않음 — 기존 결정(ADR-003)을 따른 구현
```

- 사용자가 쓰라고 이미 말했으면 판정을 보여 주고 바로 3으로 간다.
- 판정만 요청받았거나, 후보가 애매하면(기준 경계, 측정 원자료 없음) 여기서 멈추고 묻는다.
- `.records.json`의 `triggers`가 있으면 그 기준이 우선이다.

## 3. 저장소 규칙 읽기

```bash
node "${CLAUDE_SKILL_DIR}/scripts/scan.mjs" .
```

종류별 폴더, 다음 번호, 템플릿, 목록 파일과 그 형식을 알려 준다.

- 템플릿이 있으면 그 절 구성과 머리말 항목을 그대로 쓴다.
- 템플릿이 없으면 같은 폴더의 최근 문서 두 개를 읽고 구성을 따른다.
- 기록 문서가 하나도 없는 저장소면 `${CLAUDE_SKILL_DIR}/templates/`의 기본 템플릿을 쓰고, 어느 폴더에 만들지 사용자에게 묻는다.

## 4. 쓰기

- 파일 이름은 기존 형식을 따른다(`TS-058-<slug>.md` 등). 번호는 스캔 결과의 다음 번호를 쓴다.
- 측정 숫자에는 원자료 표시를 붙인다. 형식은 `references/evidence.md`.
  ```
  | p95 | 850ms <!-- src: benchmarks/search-before.json :: metrics.http_req_duration.values["p(95)"] --> | 210ms <!-- src: benchmarks/search-after.json :: metrics.http_req_duration.values["p(95)"] --> | -75% |
  ```
- 전후 비교는 같은 조건이어야 한다. 조건(데이터량, 동시성, 워밍업, 반복 횟수)을 적는다. 조건이 다르면 그 사실을 적는다.
- 결정 기록(ADR)은 확정된 것을 고치지 않는다. 결정이 바뀌면 새 ADR을 쓰고, 예전 ADR은 상태 줄만 "대체됨(→ 새 번호)"으로 바꾼다.
- 목록 파일(`_index.md` 등)에 기존 행과 같은 형식으로 한 줄 추가한다. 관련 문서끼리 링크한다.

## 5. 검사

```bash
node "${CLAUDE_SKILL_DIR}/scripts/verify-numbers.mjs" <새 문서>
node "${CLAUDE_SKILL_DIR}/scripts/scan.mjs" . --check
```

- `verify-numbers`의 ERROR(원자료와 다름, 출처 파일·경로 없음, 변화율 계산 틀림)는 모두 고친다. 원자료가 맞고 문서가 틀렸으면 문서를 고친다. 원자료가 의심스러우면 고치지 말고 사용자에게 알린다.
- WARN(출처 없는 측정 숫자)은 하나씩 처리한다: 원자료를 달거나, 실측이 아니면 "예측"을 붙이거나, 측정값이 아닌 숫자면 그대로 두고 보고에 적는다.
- `scan --check`가 목록 누락이나 번호 중복을 알리면 고친다.
