# hwpx-deliver

한컴오피스 없이 고객에게 낼 한글 문서(HWPX)와, 같은 모양의 PDF를 함께 만드는 skill입니다. 지금은 1단계(문서 만들기와 구조 검사)까지 되어 있습니다.

```
$ node scripts/build.mjs tests/fixtures/doc-long.json --out out --name 계획안
HWPX: out\계획안.hwpx
PDF:  out\계획안.pdf
$ node scripts/check-hwpx.mjs out/계획안.hwpx
구조 오류 없음
```

## 왜 만들었나

공공 사업 일을 하다 보면 결과물을 HWP와 PDF로 함께 내야 하는 경우가 많습니다. 그런데 AI에게 HWP를 만들게 하면 세 가지가 계속 걸렸습니다.

- HWP 파일 자체가 안 만들어지거나, 만들어져도 한컴에서 안 열립니다.
- PDF는 따로 만들어서 HWP와 모양이 다릅니다.
- 대화에서 나온 설명형 문장이 고객 문서에 섞여 나갑니다.

HWPX를 다루는 도구는 이미 있습니다. 한컴 없이 HWPX를 만드는 skill과 라이브러리(hwpx-skills, python-hwpx, kordoc 등)도 있습니다. 이 skill은 **같은 문서 모델 하나에서 HWPX와 PDF를 함께 뽑고, 둘이 한컴에서 같은 모양으로 나오는지를 한컴과 직접 대조해서 맞춘 것**에 무게를 둡니다.

## 어떻게 맞췄나

문서 모델(doc.json)을 HWPX(OWPML)와 인쇄용 HTML로 동시에 바꿉니다. HTML은 Edge·Chrome으로 PDF로 인쇄합니다. 같은 글꼴(함초롬바탕·돋움), 같은 mm·pt 값을 씁니다.

처음 만든 HTML은 한컴이 그린 것과 줄·쪽이 꽤 달랐습니다. 그래서 개발 PC의 한컴오피스 2022로 우리 HWPX를 열고, 한컴이 저장한 PDF와 우리 PDF의 글자 위치를 재서 비교했습니다. 이 과정에서 문서에 없는 한컴의 동작을 여럿 찾았습니다.

- 한글 글꼴의 공백을 글자 크기의 1/2로 그립니다.
- OWPML의 `KEEP_WORD`가 이름과 달리 글자 단위로 끊습니다.
- 글자처럼 취급한 표는 쪽 사이에서 나누지 않습니다.
- 쪽을 넘길 수 있는 표 다음 문단은 위 간격을 잃습니다.
- 쪽을 넘는 표의 바깥 여백을 쪽마다 다시 적용합니다. 그래서 표 위아래 간격은 바깥 여백 대신 표 앞뒤의 빈 간격 문단으로 줍니다.

전체 목록과 측정값은 [tests/oracle/README.md](tests/oracle/README.md)에 있습니다.

그렇게 맞춘 뒤의 대조 결과입니다.

| fixture | 쪽 | 줄 끝 어절이 다른 줄 | 쪽별 첫·마지막 줄 | 기준선 차이 |
|---|---|---|---|---|
| 1쪽 보고서(목록·병합 표), 38줄 | 1 / 1 | 0 | 같음 | 평균 0.14mm |
| 4쪽 계획안(쪽을 넘는 표, 쪽 나누기), 161줄 | 4 / 4 | 2 | 같음 | 평균 0.17mm |
| 2쪽 영문·숫자 혼합(36행 표), 216줄 | 2 / 2 | 0 | 같음 | 평균 0.11mm |

쪽을 넘는 표가 쪽마다 몇 행씩 들어가는지도 한컴과 같고, 쪽 번호("- 1 -") 위치 차이는 0.3mm 이내입니다. 한컴이 우리 HWPX에서 읽어 낸 텍스트는 세 fixture 모두 원래 내용과 한 줄도 다르지 않았습니다. 굵은 글씨, 병합 칸, 칸 음영도 한컴이 다시 저장한 파일에 그대로 남았습니다.

## 사용법

```
cp -r hwpx-deliver ~/.claude/skills/
```

"한글 파일로 보고서 만들어줘"라고 하면 Claude가 내용을 doc.json으로 정리해 빌드합니다. 이미 있는 HWPX의 구조만 검사하려면 `/hwpx-deliver check 파일.hwpx`라고 하면 됩니다.

Node.js와 Edge 또는 Chrome이 필요합니다. 글꼴은 함초롬바탕·함초롬돋움을 씁니다(한컴오피스나 한컴 무료 글꼴로 설치). 문서가 쓰는 글꼴이 없으면 다른 글꼴로 대체하지 않고 멈춥니다.

## 시험

```
node tests/run-tests.mjs
```

시험은 67개이고 한컴 없이 돕니다. 한컴 대조 결과(한컴이 읽은 텍스트, 작성자 정보를 지운 한컴 저장본)는 저장소에 넣어 두었습니다. 한컴과 맞추며 고친 동작을 하나씩 되돌리면, 해당 시험이 정확히 실패합니다.

- 어절 단위 줄 나눔
- 쪽을 넘기는 표
- 내어쓰기
- 굵은 글씨
- 표 바깥 여백 0과 표 앞뒤 간격 문단(HWPX·HTML)
- 칸 문단 보정을 위쪽 여백으로
- 칸 여백에서 테두리 두께 빼기

## 한계

- 한컴 2022 한 버전, 함초롬 글꼴로만 대조했습니다.
- 표 행 높이가 행마다 ±0.25mm 어긋납니다. 브라우저가 1/96인치 단위로 맞추기 때문입니다. 대조한 표(36행)에서는 오차가 쌓이지 않았지만, 행이 쪽 끝에 아슬아슬하게 걸치면 다르게 나눌 수 있습니다.
- 쪽 번호는 아래 가운데만 됩니다.
- 줄 폭에 아슬아슬하게 맞는 줄은 한컴과 다른 어절에서 끊길 수 있습니다.
- 한컴에서 열리는지는 한컴 없이 100% 확인할 수 없습니다. 구조 검사는 알려진 원인만 잡습니다.
- 아직 없는 것: 기존 HWPX 양식 채우기, 원자료(회의록·RFP) 읽기와 근거표, 납품 전 검사(대화체·숫자 대조), 바이너리 .hwp 읽기.
