# 한컴 대조 (개발 검증용)

skill은 한컴오피스 없이 돈다. 이 폴더의 도구는 개발할 때만 쓴다. 한컴이 깔린 Windows에서 우리가 만든 HWPX를 한컴으로 열어 보고, 한컴이 그린 PDF와 우리 PDF를 비교한다.

```
node tests/oracle/roundtrip.mjs tests/fixtures/doc-long.json long
```

- `hancom-open.ps1`: 한컴 COM(`HWPFrame.HwpObject`)으로 HWPX나 HWP를 열고 PDF·HWPX로 다시 저장하고, `GetTextFile("UNICODE")`로 텍스트를 뽑는다. 한컴은 임시 폴더 밖 파일을 열 때 '접근 허용' 창을 띄우므로 `%TEMP%` 아래 복사본만 다룬다.
- `compare_pdf.py`: 두 PDF의 줄 기준선 위치, 줄 끝 어절, 쪽별 첫·마지막 줄을 비교한다(PyMuPDF 필요). 같은 높이의 글자 조각은 실제 글자 상자 끝에서 3mm 안에 있을 때만 한 줄로 합친다(표 칸은 따로 남는다).
- `expected/*.hancom.txt`: 한컴이 읽어 낸 텍스트. 저장소 시험(`tests/run-tests.mjs`)이 한컴 없이 이걸로 비교한다.

## 측정 결과 (2026-11-25, 한컴오피스 2022 12.0.0.535, Edge headless)

`roundtrip.mjs` 출력 값이다. 줄 수에는 쪽 번호 줄이 들어 있다.

| fixture | 쪽 | 쪽별 줄 수 | 줄 끝 어절이 다른 줄 | 쪽별 첫·마지막 줄 | 기준선 차이 |
|---|---|---|---|---|---|
| doc-basic (1쪽, 목록·병합 표) | 1 / 1 | 38 / 38 | 0 | 같음 | 최대 0.49mm, 평균 0.14mm |
| doc-long (4쪽, 쪽을 넘는 표, 쪽 나누기) | 4 / 4 | 53·64·4·40 / 53·64·4·40 | 2 (문단 2곳) | 같음 | 최대 0.43mm, 평균 0.17mm |
| doc-mixed (2쪽, 영문·숫자·URL, 36행 표) | 2 / 2 | 125·91 / 125·91 | 0 | 같음 | 최대 0.38mm, 평균 0.11mm |

쪽을 넘는 표가 쪽마다 몇 행씩 들어가는지도 같다(doc-long 1쪽 5행, doc-mixed 1쪽 20행). 행 간격은 한컴 4.53mm, 브라우저는 4.49·4.76mm가 섞여 평균 4.52mm이다. 20행을 쌓은 뒤 마지막 행 기준선 차이는 0.09mm였다.

## 대조로 찾은 한컴의 동작

처음 만든 HTML은 한컴과 줄·쪽이 꽤 달랐다. 아래는 PDF를 재서 찾은 차이와 맞춘 방법이다.

| 한컴의 동작 | 맞춘 방법 |
|---|---|
| 한글 글꼴의 공백을 글자 크기의 1/2로 그린다(본문 11pt에서 1.93mm, 브라우저는 1.41mm) | 브라우저의 실제 공백 폭을 재서 `word-spacing`으로 채움 |
| 줄 높이 = 글자 크기 × 줄 간격%, 기준선은 줄 위에서 글자 크기 × 0.85 | 브라우저가 쓰는 ascent·descent를 재서 문단을 그만큼 올림 |
| `breakNonLatinWord="KEEP_WORD"`가 글자 단위로 끊는다("완료되/었다."). `BREAK_WORD`가 어절 단위 | HWPX에 `BREAK_WORD`, HTML은 `word-break: keep-all` |
| 내어쓰기: 첫 줄은 `left`에서, 둘째 줄부터 `left + |intent|`에서 시작 | `left`를 첫 줄 위치로 씀 |
| 표 칸 높이에 마지막 줄의 줄 간격과 테두리 두께를 넣지 않는다 | 칸 문단에 음수 위 여백(아래 여백으로 주면 줄 상자가 칸 아래로 삐져나와 브라우저가 그만큼 일찍 행을 넘긴다), 칸 여백에서 테두리 절반을 뺌(브라우저는 1픽셀보다 가는 테두리를 1픽셀로 그림) |
| 글자처럼 취급한 표(`treatAsChar=1`)는 쪽 사이에서 나누지 않고 통째로 다음 쪽으로 넘긴다 | `treatAsChar=0`, 머리 행 반복(`repeatHeader`, HTML `thead`) |
| 쪽을 넘는 표의 바깥 여백(`outMargin`)을 쪽마다 적용한다. 위 여백은 다음 쪽에서도 다시 들어가고, 아래 여백만큼은 쪽 끝에 자리를 남기고 행을 넘긴다 | 표 바깥 여백은 0. 위아래 간격은 표 앞뒤의 빈 간격 문단(글자 크기 = 간격, 줄 간격 100%)으로 주고 HTML도 같은 높이의 빈 문단을 둠 |
| 쪽을 넘길 수 있는 표 바로 다음 문단은 위 간격(prev)을 잃는다 | 간격 문단을 두므로 지금 서식에서는 해당 없음. 표 아래 간격이 0이면 HTML도 표 다음 문단의 위 간격을 없앰 |
| 쪽 번호(`pageNum`)는 "쪽 번호" 글자 스타일이 없으면 다른 글꼴로 그린다. 기준선은 아래 여백 경계에서 글자 크기 × 0.31 위(10pt에서 1.1mm, 꼬리말 높이 7mm일 때) | header.xml에 "쪽 번호" 글자 스타일을 넣고, HTML은 `@page` 아래 가운데 상자에 같은 위치로 그림(오차 0.3mm 이내) |

## 남은 차이

- 브라우저는 표 행 높이를 1/96인치 단위로 맞춰서 행마다 ±0.25mm 어긋난다. 위 fixture에서는 오차가 쌓이지 않았고 쪽 나눔도 같았다. 다만 행이 쪽 끝에 0.3mm 안쪽으로 걸치면 다르게 나눌 수 있다(이 경우는 재 보지 않았다).
- 줄 폭에 0.5mm 안쪽으로 아슬아슬하게 맞는 줄은 한컴과 다른 어절에서 끊길 수 있다(doc-long의 문단 2곳). 원인은 확인하지 못했다(추측: 한컴은 글자 위치를 1/600인치 격자에 맞춰 그리고, 브라우저는 글자 폭을 조금 짧게 계산한다).
- 쪽 번호는 아래 가운데만 대조했다. 다른 위치는 모델에서 받지 않는다.
- 한컴 2022 한 버전, 함초롬 글꼴로만 확인했다. 다른 버전이나 다른 글꼴에서는 다시 재야 한다.
