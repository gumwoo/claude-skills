인자: $ARGUMENTS

스크립트는 `${CLAUDE_SKILL_DIR}/scripts/`에 있고 Node.js로 돈다. 외부 패키지와 한컴오피스가 필요 없다. PDF는 설치된 Edge·Chrome으로 인쇄한다.

## 원칙

- 원자료에 없는 사실은 쓰지 않는다. 근거가 없는 내용은 고객 문서에 "작성 필요" 같은 표시로 남기지 않고 `pending`(미결 목록)으로 뺀다.
- 고객 문서에 대화체·설명형 문장("이 보고서는 …를 바탕으로 작성했습니다", "확인 필요", "말씀하신")을 넣지 않는다.
- 근거표·미결 목록·검사 결과는 내부 자료다. 고객 파일과 다른 폴더에 둔다.
- 사용자 저장소나 원자료 파일을 바꾸지 않는다. 결과물은 사용자가 정한 폴더에, 정하지 않았으면 물어본다.
- 글꼴은 대체하지 않는다. 문서가 쓰는 글꼴이 PC에 없으면 빌드가 멈춘다. 다른 글꼴로 그리면 한컴과 줄·쪽 나눔이 달라지기 때문이다.
- 검사 규칙은 의심을 알리는 것이다. 오탐이면 검사를 통과시키려고 문장을 어색하게 바꾸지 말고, 보고에 오탐이라고 적는다.

## 인자가 check이면

`node "${CLAUDE_SKILL_DIR}/scripts/deliver-check.mjs" <파일.hwpx>`를 돌려 결과를 그대로 보고한다. 구조 검사(S1)와 문장 검사(L1~L3, F1)를 한다. 원자료 파일도 주면 먼저 `read-sources.mjs`로 읽고 `--sources`를 붙여 숫자를 원자료에서 찾는다. 종료 코드 2는 오류가 있다는 뜻이다.

## 원자료 읽기

1. 원자료를 조각으로 나눈다. 결과는 임시 디렉터리에 둔다.
   ```
   node "${CLAUDE_SKILL_DIR}/scripts/read-sources.mjs" <파일...> --out <작업 폴더>
   ```
   - 읽는 형식: `.txt`·`.md`(클로바노트 회의록은 발언 단위), `.hwpx`, `.docx`, `.xlsx`
   - `.pdf`: 스크립트가 읽지 않는다. Claude가 PDF를 Read로 읽고, 필요한 쪽을 요약하지 말고 그대로 `<이름>.pdf.txt`로 옮겨 적는다. 쪽마다 `=== p.3 ===` 줄을 넣고, 그 파일을 원자료로 넣는다.
   - 바이너리 `.hwp`: 아직 못 읽는다. 사용자에게 한컴에서 HWPX로 저장해 달라고 하거나, 그럴 수 없으면 원문을 텍스트로 받는다.
2. `<작업 폴더>/sources.txt`를 끝까지 읽는다. 조각 id(`S1:12`, `S1:h2`, `S2:p3.1`, `S3:t1.r2c3`, `S4:견적!B3`)가 근거를 가리키는 이름이다.
3. 사용자가 문서 종류와 목차를 정하지 않았으면, 목차안과 장마다 들어갈 내용 한 줄을 먼저 보여 주고 확인받는다.

## 문서 만들기

1. 내용을 문서 모델로 정리한다. 형식은 `${CLAUDE_SKILL_DIR}/scripts/lib/model.mjs` 맨 위 주석에 있다.
   - 블록: `title`, `heading`(level 1~3), `para`, `list`(level 1~3, 기호 □ ○ -), `table`(widths_mm, header_rows, rowspan·colspan), `pagebreak`
   - 굵게 쓸 부분은 `[{ "t": "...", "b": true }]`
   - 제목 번호(1. 2.)는 글자로 직접 쓴다
   - 표 열 너비 합은 본문 폭(A4, 좌우 여백 20mm → 170mm)을 넘지 않게 한다
   - 쪽 번호는 기본으로 아래 가운데 "- 1 -"이다. 빼려면 `"page": { "number": false }`
2. 원자료로 쓸 때는 근거를 붙인다.
   - 내용이 있는 블록과 표 칸마다 `"src": ["S1:3"]`. 숫자·날짜·금액은 그 조각에 있는 값을 쓴다(표기는 바꿔도 된다: "1억 2,000만 원" → "120,000,000원")
   - 원자료 숫자로 계산한 값은 `"calc": "120,000,000원 ÷ 6개월 = 20,000,000원"`
   - 근거가 없거나, 발언끼리 서로 다르거나, 해석이 갈리는 내용은 문서에 넣지 않고 `"pending": [{ "item": "...", "reason": "...", "src": [...] }]`
   - 회의록은 말이다. 보고서 문체(개조식 또는 합쇼체)로 옮기고, 말버릇·추임새·"~요" 끝맺음을 남기지 않는다. 필요한 경우가 아니면 누가 말했는지 쓰지 않는다
   - 회의록에는 음성 인식 오류가 섞여 있다. 같은 대상이 다르게 적히거나(기관·사람 이름), 문맥에 맞지 않는 숫자가 나오면 추측해서 고치지 않는다. 그 내용은 `pending`에 원문 조각 id와 함께 넣고 사용자에게 묻는다. 숫자 대조(N1)는 잘못 인식된 숫자를 그대로 옮겨도 통과한다
3. doc.json을 임시 디렉터리에 저장하고 빌드한다.
   ```
   node "${CLAUDE_SKILL_DIR}/scripts/build.mjs" doc.json --out <결과 폴더> --name <파일 이름>
   ```
   결과 폴더에 `<이름>.hwpx`와 `<이름>.pdf`가 생긴다. `_build/`에는 PDF를 그린 HTML이 남는다. 고객에게는 보내지 않는다. `src`·`calc`·`pending`은 고객 파일에 들어가지 않는다.
4. 납품 전 검사를 돌린다. `--report`에는 결과 폴더와 다른 내부 폴더를 준다.
   ```
   node "${CLAUDE_SKILL_DIR}/scripts/deliver-check.mjs" doc.json --sources <작업 폴더>/sources.json --report <내부 폴더>
   ```
   - 오류(종료 코드 2)는 고치고 다시 빌드한다. N1(원자료에 없는 숫자)은 원자료를 다시 보고 값이나 `src`를 고친다. 근거를 못 찾으면 그 내용을 `pending`으로 뺀다
   - 경고는 하나씩 판단한다. 맞으면 고치고, 오탐이면 그대로 두고 보고에 적는다
   - 내부 폴더에 `근거표.md`, `미결·확인필요.md`, `검사결과.md`가 생긴다
5. `node "${CLAUDE_SKILL_DIR}/scripts/check-hwpx.mjs" <이름>.hwpx`로 구조를 검사한다.
6. PDF를 직접 열어 본다(Read로 페이지 확인). 표가 넘치거나 제목이 쪽 끝에 혼자 남았는지 본다.
7. 보고: 고객 파일 경로와 쪽수, 내부 자료 경로, 검사 결과(오류·경고 수, 남긴 경고와 그 이유), 미결 목록.

## 양식 채우기 (사용자가 HWPX 양식을 줄 때)

양식은 문서마다 다르다. 양식을 고정해 두지 않고, 받은 양식을 그때그때 읽는다.

1. 양식이 `.hwp`면 아직 못 읽는다. 한컴에서 HWPX로 저장해 달라고 한다.
2. 양식 지도와 채울 칸 후보를 본다.
   ```
   node "${CLAUDE_SKILL_DIR}/scripts/scan-template.mjs" <양식.hwpx>
   ```
   - 주소: 본문 문단 `P3`, 표 `T1`, 칸 `T1.r2c1`, 칸 안 문단 `T1.r2c1.p5`, 칸 안 표 `T1.r3c1.T2`
   - 후보: `{{키}}`, ○○, 누름틀, 이름 붙은 칸, 항목 이름 뒤에 적는 칸, 항목 이름 옆 빈 칸, 본문 자리(빈 문단), 반복 행, 서식 안내문
   - 후보는 추정이다. 양식 지도를 끝까지 읽고 채울 곳을 정한다. 공문 서식처럼 "행정기관명", "직위(직급) 서명" 같은 용어 자체를 내용으로 바꿔 쓰는 칸도 있다(서식의 비고·작성 방법을 읽는다)
3. 원자료가 있으면 "원자료 읽기"대로 읽는다.
4. **확인 ①:** 채울 칸 목록, 칸마다 넣을 내용 한 줄, 지울 것(서식 안내문, "■ … [별지 제○호서식]" 머리 줄 등), 근거가 없어 비워 둘 칸을 보여 주고 확인받는다.
5. fill.json을 쓴다. 형식은 `${CLAUDE_SKILL_DIR}/scripts/fill-template.mjs` 맨 위 주석에 있다.
   - 칸 전체: `{ "at": "T1.r6c2", "text": "..." }`. 여러 줄이면 `\n`
   - 항목 이름 뒤에 적기, 용어 바꾸기: `{ "at": "T1.r2c1.p5", "find": "제목 ", "text": "제목  …" }`
   - 반복 행: `{ "table": "T2", "from_row": 2, "rows": [[...], ...] }`. 빈 행을 먼저 채우고, 모자라면 행을 복제해 늘린다
   - 행 지우기: `{ "delete_row": "T1.r11" }`. 위에서부터 지우면 아래 주소가 바뀌므로 아래 행부터 지운다
   - 양식의 빈 문단이 가운데 정렬 같은 자리 잡기용 문단이면 `"like": "<모양을 빌릴 문단 주소>"`
   - op마다 `"src"`(반복 행은 행별 `"row_src"`), 계산한 값은 `"calc"`. 근거가 없는 칸은 채우지 않고 맨 위 `"pending"`에 넣는다
   - ops는 차례로 적용되고, 하나 적용할 때마다 주소를 다시 매긴다. 행을 지우거나 늘린 뒤의 op는 바뀐 주소를 쓴다
6. 채운다. 결과는 고객 폴더에, 양식 파일은 그대로 둔다.
   ```
   node "${CLAUDE_SKILL_DIR}/scripts/fill-template.mjs" <양식.hwpx> fill.json --out <결과.hwpx>
   ```
   "원래보다 N자 길어짐" 경고가 나온 칸은 고정 크기 상자에서 줄이 접히거나 넘칠 수 있다.
7. 납품 전 검사: `deliver-check.mjs fill.json --sources … --report <내부 폴더>`로 넣은 값과 근거를, `deliver-check.mjs <결과.hwpx>`로 결과 문서 전체를 검사한다.
8. 보고: 결과 파일, 채운 칸·지운 행 목록, 검사 결과, 길어짐 경고가 난 칸, 미결 목록. 채운 양식의 PDF는 아직 만들지 못한다고 알린다(한컴이 있으면 한컴에서 PDF로 저장).

## 한계 (사용자에게 그대로 알린다)

- 한컴이 실제로 여는지는 한컴 없이 100% 확인할 수 없다. 구조 검사는 알려진 원인만 잡는다.
- PDF는 같은 서식을 브라우저로 그린 것이다. 한컴 2022와 대조한 fixture 3개(1·2·4쪽, 쪽을 넘는 표 포함)에서는 쪽 나눔과 쪽 번호 위치가 같았다. 다만 줄 폭이 아슬아슬한 줄은 다른 어절에서 끊길 수 있고, 표 행이 쪽 끝에 아슬아슬하게 걸치면 다른 행에서 나뉠 수 있다. 측정 결과는 `tests/oracle/README.md`에 있다.
- 클로바노트 회의록: 작성자·시간을 둘 다 넣거나 둘 다 뺀 내보내기는 실제 파일로 확인했다. 하나만 넣은 모양은 실제 파일로 확인하지 못했다. `sources.txt`에서 발언이 제대로 나뉘었는지 확인한다.
- 숫자 대조(N1)는 문서의 숫자가 인용한 조각에 있는지만 본다. 숫자의 뜻(무엇의 금액인지)이 맞는지는 Claude가 근거표로 확인해야 한다.
- 문장 검사는 정해 둔 표현만 잡는다. 공문서 항목 기호 순서와 금액 한글 병기는 검사하지 않는다.
- 양식 채우기는 글자만 넣는다. 굵게 같은 새 글자 모양은 만들지 않고, 그 자리의 모양이나 `like`로 빌린 모양을 따른다. 글자 폭을 재지 않으므로 칸이 넘치는지는 알 수 없다. 누름틀은 찾기만 하고, 누름틀 안 글자는 `find`로 바꾼다.
- 아직 없는 것: 채운 양식의 PDF, 바이너리 .hwp 읽기, PDF 직접 읽기, 문서 간 일치 검사(엑셀 추적표 ↔ HWPX).
