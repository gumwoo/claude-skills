# 변경 검증

완료 보고 전에 아래 순서로 검증한다. 실행하지 않은 항목은 "검증 못 함"으로 보고한다.

## 1. 변경 범위 확인

```
git status --short
git diff --stat HEAD
```

## 2. 전체 검증 (<측정 시간>)

```
<전체 검증 명령>
```

실패하면 출력으로 원인을 찾아 코드를 고친다. 검사 명령, 테스트 기대값, 기준선 파일을 고쳐서 통과시키지 않는다.

## 3. 관련 테스트만

```
<스택별 단일·부분 테스트 명령>
```

## 4. 실행 확인

<앱 실행·확인 방법. 문서에만 있으면 "문서에 적힌 방법(실행 확인 안 함)"이라고 표시. 서버처럼 끝나지 않는 명령이면 "사용자 승인 후 백그라운드로 띄우고 확인한 뒤 종료한다". 적힌 곳이 없으면: "미정. 처음 실행할 때 사용자에게 묻고 이 skill에 추가한다">

DB나 외부 시스템에 붙는 실행은 사용자 승인 후에만 한다.

## 5. 반복 한도

같은 검사가 3번 고쳐도 실패하면 멈추고 실패 출력과 시도한 내용을 보고한다. sleep, 재시도, 테스트 건너뛰기로 통과시키지 않는다.

`/goal`이 걸린 세션이라면 판정하는 모델은 대화만 읽는다. 검증 명령은 직접 실행하고, 종료 코드와 핵심 출력이 대화에 남게 한다.

## 6. 보고 형식

```
검증
- 실행: <명령> → <통과/실패, 핵심 출력 한 줄>
- 검증 못 함: <항목과 이유>
```
